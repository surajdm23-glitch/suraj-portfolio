An AI‑Assisted Design Workflow

The method behind everything I've shipped recently - AI as a continuous critic, not a generator, questioning and validating at every stage so ambiguity gets argued out before engineering ever sees it.

Design System
01
Philosophy

AI doesn't replace my thinking. It strengthens it.

A companion, not a generator - the one rule this method doesn't bend on.

I don't ask AI to design a screen. I ask it to argue with the one I've already drafted - before I present anything to a PM, I run their brief past it first, not for an answer but for pushback.

I think
→
AI critiques
→
I decide

“A standing critic - consulted before the meeting, during the exploration, and again before anything ships.”

04
Worked Example

Rate Card: where the workflow became tangible.

Not a conventional product case study. This is evidence of how the work moved from an inherited, difficult-to-change implementation to Rate AI—and how my design-to-implementation loop changed along the way.

Legacy code
Starting constraint

An operational product that felt untouchable

The existing Rate Card experience predated my involvement. Its implementation was difficult to modify, while the workflow remained largely manual. The problem was not simply to refresh the interface; it was to create a credible path from legacy software to a product that could evolve.

Phase 1
Legacy → modernised operations

Designing against the real implementation

The first phase modernised the operational experience and addressed immediate product problems. It was still a manual Rate Card workflow—there was no Rate AI or agent experience. The important shift happened in how I worked: VS Code and Claude Code let me explore, modify, run, and test ideas closer to the existing product instead of designing a separate idealised surface.

Output
Design delivery → manual-operation handover

What Phase 1 actually delivered

Phase 1 closed with a modernised, manual-operation Rate Card product handed over as the working baseline — before Rate AI, FarEye's Pilot AI product, entered the picture. This was the deliverable Phase 2's Rate AI work would later build on top of.

The loop
AI-assisted design + implementation

The handoff became a continuous feedback loop

Product thinking, UX decisions, code-level experiments, and implementation validation stopped happening as separate blocks. Each pass could expose constraints and edge cases early enough to influence the next design decision.

Working surface · VS Code + Claude Code + local product
Understand→ Explore→ Design→ Prototype→ Implement→ Validate→ Iterate

AI supported the work between these steps—helping inspect the implementation, test alternatives, surface issues, and shorten the distance between an interaction decision and evidence from working software.

Phase 2
Modernised operations → Rate AI

The product became AI-assisted too

The second phase introduced Rate AI Product design. The same close design-and-code workflow now supported a larger product shift: moving beyond manual configuration toward an experience where AI could help people inspect, resolve, and act on rate information. This was the point where AI-assisted delivery and an AI-enabled product became visible together—without being the same thing.

Outcome
What changed

A more intelligent product—and a tighter way of making it

The outcome was not one redesign. It was a sequence: first, a modernised Rate Card experience; then, Rate AI. Just as importantly, the project established a repeatable way to move between design intent, implementation reality, and validation without waiting for a formal handoff at every turn.

Product capability

Legacy Rate Card → modernised operational workflow → Rate AI.

Workflow capability

Design ↔ code ↔ local validation became a continuous loop rather than three separate stages.
